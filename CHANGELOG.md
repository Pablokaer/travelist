# Changelog

Every change to Wayfarer is recorded here: features, fixes, data (each city added or re-ingested), backend, tooling and docs. Newest first. Format based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/); sections: **Added**, **Changed**, **Fixed**, **Removed**, **Data**, **Docs**.

How to record a change (enforced in CI by `scripts/check-docs.mjs`):

1. Add a line under **Unreleased** in the same commit as the change — what changed for the user or developer, not how.
2. New or changed feature → also update [README → Features](./README.md#features) (and _Backend reference_ / _Limits and rules_ when relevant).
3. City added or removed → list it under **Data** by name; `docs/CITIES.md` is regenerated by the pipeline.
4. When a milestone or release is cut, rename **Unreleased** to the date / version and start a new one.

## Unreleased

### Added

- Public traveller profiles (D-045): the author's name on a review and on a chat message is a link to their profile (`/traveller?id=…`): photo, name, "Member since {month year}", the number of public walk lists and those lists (newest first, with View / Save and **Load more**; never private or password lists). Your own profile says it is how others see you. Backend: `profiles.public_id` (links never expose the account id), `public_profile` RPC, `author_public_id` in `list_reviews` / `list_walk_messages` / `list_walklists`, and `list_walklists(p_author)` (new migration).

- Walk list group chat (D-043): saying **I'm going** to a walk list meetup gives access to its **group chat**, shared by everyone going and the organiser, with instant messages (Supabase Realtime). **Open group chat** appears on the shared list's meetup banner (for members) and on the organiser's list page; the chat (`/walk-chat?id=…`) shows the messages oldest first with each author's name and photo, own messages on the right, and a field to write (up to 1000 characters). "Not going" leaves the chat; people who only want the list can save it instead ("Going adds you to the group chat. Rather not? Just save the list."). Backend: `walk_messages` (members read and write; no edit or delete), `is_walk_chat_member`, `list_walk_messages`, Realtime publication (new migration).

- Scheduled data refresh with a data gate (D-042):
  - **Monthly** (`.github/workflows/data-refresh.yml`, 1st of the month, or run by hand for chosen datasets): countries, visa rules, city "About" texts and every city's attractions are fetched again and gated against main. The seeds are regenerated and a pull request opens with the gate report; nothing is published without review.
  - **The gate** (`python -m wayfarer_pipeline gate`) restores from the committed data any text that got worse (empty, markup, a disambiguation page, a raw Wikidata id, a summary shrunk below 40%), any lost photo with its credit, and any country fact that vanished. It lists changed plugs, voltages, emergency numbers, currencies and visa rules for review. It blocks when a city loses more than 15% of its places or has 30% replaced, visa rules drop by more than 1% or change by more than 10%, a country or city file goes missing, or more than a quarter of the texts needed restoring.
  - **In CI**, the same gate runs on every pull request against its base branch; the `data-gate-override` label skips it for an intended big change.
  - **Weekly** (`.github/workflows/providers-check.yml`): a live check of Open-Meteo, Frankfurter / ExchangeRate-API and Global Affairs Canada through the production providers (`checklist/live-check.ts`) opens or updates a `data-source` issue when one fails.
- Walk meetups (D-041): a walk list can have a date and time, so travellers walk it together. Choose an optional **Start time** (HH:MM, in the city's time) with the date when saving a route, or set, move or remove it later on the list page (**Date and time**); it must be in the future. The city page shows **Upcoming meetups** — the next 5 public lists with a time, ranked soonest first with a live countdown ("Starts in 2 d 3 h"), local date and time, and how many are going — and **View all meetups** (`/short/{slug}/meetups`) lists every upcoming one by day (Today, Tomorrow, dates). Shared list pages show **Walk together** with the start, countdown and **I'm going** / **Not going** for signed-in travellers (not the organiser; not after the start). Backend: `trips.starts_at` (keeps `trip_date` in the city's day), `walk_attendees`, `set_trip_schedule`, `save_trip(p_starts_at)`, `list_walklists(p_upcoming, sort 'soonest')` and `shared_trip` return the start and attendance (new migration).

- Profile photo (D-039): on Edit profile, **Add photo** / **Change photo** picks a photo from the library (native crop on iOS/Android, file dialog on web), which is cropped to the centre square, resized to 512 px and uploaded as JPEG. **Remove photo** goes back to the initials. The photo shows on the Profile screen and next to the user's reviews. Deleting the account deletes the photo files. Backend: public `avatars` Storage bucket (2 MiB, JPEG / PNG / WebP) with per-user folder policies, `profiles.avatar_path`, and `list_reviews` returns `author_avatar_path` (new migration). New dependencies: `expo-image-picker`, `expo-image-manipulator` (photo library permission text in `app.json`).
- Walk list cards show the photo of the list's starting point (D-038), with its credit, on My Trips (own and saved lists), on the city page (community and official) and on View all walk lists. When the start has no photo the card uses the next stop that has one, and the placeholder when none does. Backend: `walklist_cover(trip)` (also a computed column on `trips`), and `list_walklists` returns `cover` (new migration).
- Demo community data for local testing (D-037): `pnpm db:demo amsterdam` loads six demo friends (English, Spanish and French) and the "Wayfarer Team" moderator into the local database, all signing in with `wayfarer-demo`. Amsterdam gets 6 city reviews (avg 4.5), 35 reviews of 10 places, 9 public community walk lists and 4 official ones, 42 walk list ratings among the friends and 12 saved lists, all 4–5 stars. A self-check then runs through `list_walklists`, `list_reviews` and `rating_summary`. Local only: kept in `supabase/demo/`, outside the seeds that `db push --include-seed` ships.
- City page (D-033): a city card on the Home now opens the city's own page, `/short/{slug}`: cover photo with its credit, name, flag + country, the city's average rating and **Explore attractions**, which opens the existing Map / List page (`/city/{slug}`, unchanged). Then **About {city}** (Wikipedia lead with attribution and link), **Top community walk lists**, **Official walk lists**, **Before you go** (the checklist sections for a trip starting today, **Choose your dates** for the full page) and **Reviews**. Each section has its own loading, empty and error state.
- City reviews and walk list reviews (D-034): signed-in users rate a city or someone else's shared walk list with 1–5 stars and an optional comment — one review per user, editable and deletable only by its author — with the average, the number of reviews and bars of reviews per star. Attraction pages show the per-star bars too. Backend: `attraction_reviews` becomes `reviews` with exactly one target (attraction, city or trip), `save_review` / `list_reviews` take the target, new `rating_summary` view (new migration).
- Community and official walk lists (D-035): the city page previews the 6 best rated public lists of travellers and the official lists (marked by moderators, "Official · by Travelist"), as cards with author, rating, stops, distance, walk, **View** and **Save**. **View all walk lists** (`/short/{slug}/walklists`, `?kind=official` for official ones) searches by name, sorts by Highest rated / Lowest rated / Most reviewed / Newest and loads 20 at a time. **Save** keeps other people's lists under My Trips → **Saved**. Shared list pages show the author and rating to everyone and let signed-in visitors save and rate the list; moderators mark public lists official. Backend: `saved_trips`, `moderators`, `trips.is_official`, `list_walklists`, `is_moderator`, `set_trip_official`, `shared_trip` returns author / official / rating / saved (new migration).
- About screen lists Wikipedia (city descriptions, CC BY-SA 4.0) among the data sources.

- City page rating filter (D-032): after the category tabs, **★ 3+**, **★ 4+** and **★ 5+** tabs show only the places whose average rating reaches that many stars (grid, map and count); places without reviews are hidden while one is active. Pressing the active tab again shows every place; it combines with the categories and the search.
- Walk list visibility (D-031): every saved trip is **Private** (default; only the owner), **Public** (anyone with the link, signed in or not) or **With password** (anyone with the link and the password the owner chose, 4–72 characters). The owner changes it on the trip page ("Who can see this list" → **Save visibility**) at any time; **Share list** (public or password lists only) opens the share sheet or copies the link. The link `/shared?id=<trip id>` opens a read-only view (map, totals, stops, walking links) for anyone; protected lists ask for the password, private or missing ones say "Walk list not available". My Trips marks shared lists (Public / With password). Backend: `trips.visibility`, `trip_passwords` (bcrypt hashes no client can read), `set_trip_visibility` and `shared_trip` RPCs (new migration); optional `EXPO_PUBLIC_WEB_URL` for the links.
- City page map (D-029): places are round photo markers (their own 120 px photo in a white ring, or the photo placeholder; stop number when in the route) instead of coloured dots. The first tap selects a marker and opens the compact List card over the map (photo, name, category · visit time, rating, **+**); **+** adds to the route and stays on the map, tapping the card opens the place, another marker or an empty spot moves or closes the card. Built on maplibre's own `Marker` and `Popup` (web) and MapLibre React Native's `Marker` (iOS/Android); the route and trip maps keep their numbered dots.
- City page cards show the place's average rating beside its name ("3.5 ★", gold star), for places with reviews; `attraction_rating_summary` gains `city_slug` so a city's ratings come in one request (new migration).
- Attraction reviews (D-028): on each attraction, signed-in users rate it with 1–5 clickable gold stars and an optional comment, see every review (author name, stars, date, comment, newest first) and the average with the number of reviews next to the name ("4.6 ★ · 128 reviews"). One review per user and place — publishing again edits it — and users can delete only their own. Backend: `attraction_reviews` table with RLS, `save_review` and `list_attraction_reviews` RPCs, `attraction_rating_summary` view (new migration).
- Route builder: stops can be reordered by **dragging** their grip (⋮⋮) as well as with move up / move down (D-027). The dragged stop follows the pointer, the others slide to make room, the page stops scrolling during the drag, and dropping switches to manual order like the buttons do.
- `./run-project.sh`: one command to run the project locally — starts Docker, installs dependencies, starts Supabase, fills `.env` with the local keys, serves the Edge Functions and opens the web app; `--stop` stops the Supabase stack.
- Home page (D-026): after sign-in the app opens on a grid of the destinations it covers (only active cities with data) — cover photo with its credit, city, country and number of places — with a **Search cities** field (city names in EN/PT, then countries). A city card opens the city page at `/city/{slug}` (e.g. `/city/amsterdam`), which is the former Explore screen, now driven by the city in the URL; the logo, the Explore tab and back return to the Home. `city_list` gains the country names and a cover photo (new migration).

### Fixed

- Walk list group chat (D-044): messages could stay invisible to other participants when a Realtime event was lost (e.g. after the Realtime service restarted); the chat now also re-reads its history on open, on focus (app back in the foreground included) and every 10 s while open, so every message shows. "I'm going" could fail when repeated (duplicate) and showed no error on failure; it is now idempotent (`set_walk_attendance`, new migration), reports failures and always shows the server's state.

- Private walk lists (D-040): the reviews and rating of a private list were readable by anyone who guessed its id; now only its owner sees them (new migration). Opening someone else's list at its editing address (`/trip/{id}`) now shows the read-only view — the list if it is public, "Walk list not available" if it is private — instead of an error.

- Route builder: after removing a stop, dragging another stop to the last place did nothing (the removed stop's row still counted as a drop slot).
- Route builder: a drag interrupted by the system (e.g. a notification gesture) no longer moves the stop; only releasing the grip drops it.
- Route builder: the remove button's screen-reader label uses the stop's name in the app language (it was always English).

### Changed

- Walk list participation (D-044): **I'm going** (PT: **Quero participar**) is on every public walk list — with or without a date and time, before or after its start — so any public list gathers people in its group chat; the chat lists its people ("3 people: Ana (organiser), You, Cid") and stays above the keyboard on phones; the organiser opens the chat from any public list's page.

- Trip page split into `features/trips/trip-view.tsx` (shared by the owner's page and the shared link) and the owner's actions; the backend E2E helpers moved to `e2e/helpers.ts`.
- No company name in the project: the placeholder bundle id / Android package is now `com.travelist.app` (D-001); the Edge Functions' User-Agent points at the real repository (`github.com/Pablokaer/travelist`); the data pipeline's default contact is the repository URL (override with `PIPELINE_CONTACT_EMAIL`).
- Brand: the app is shown as **Travelist** instead of Wayfarer — the logo wordmark and its "Travelist — all destinations" label, the About page, the app name (`app.json`, browser tab and home screen) and the sign-in / confirmation emails (templates and subjects). Code names are unchanged: repository, `@wayfarer/*` packages, the `wayfarer://` scheme and the bundle id.
- Routes hold up to 20 stops (D-030; the limit was 12): the tray, the `route-optimize` request schema and `save_trip` accept 2–20 stops, and the "route is full" notice now says 20 (new migration widens the `trip_stops.position` check to 0–19). Up to 12 stops the order stays exact; for 13–20, nearest neighbour + 2-opt. "Suggest a split" still offers at most 6 routes and caps its search work so it stays interactive.
- `AttractionCard` moved to `features/destinations/attraction-card.tsx` (with a `compact` variant) and `Thumbnail` to `features/destinations/thumbnail.tsx`, keeping `components.tsx` under 500 lines; `@types/react-dom` added (dev) for the map's portals.
- Route builder performance: reordering a stop updates the list in place instead of rebuilding every row (the route list was keyed by its stop order), and while dragging the list only re-renders when the hovered slot changes, not on every pointer move (D-027).
- Route optimisation (D-025): on-device ordering, split routes and the offline fallback now find the exact shortest walk (Held-Karp) instead of nearest neighbour + 2-opt, which walked up to 21% further on 46% of random 12-stop routes (about 2% on average); `route-optimize` makes one OpenRouteService request per route instead of two (the optimisation returns the geometry and leg totals); the ORS cache matches the same places in any order, so optimising again after the app applied the order is a cache hit; the route screen only re-sends routes that changed.
- Explore layout (D-024): the header shows the Wayfarer logo and fits logo, city + search and **Before you go** in one row on wide screens (about 70 px shorter on desktop); the search is a centred group capped at 640 px instead of spanning the page; category tabs are a centred group that scrolls edge to edge on phones; header and card grid share one container (1440 px), and the grid picks its columns from its own width (3–5 on desktop instead of the window-based 1–4). The desktop rail is narrower (96 px) and lines up with the header.
- Route builder: "Suggest a split" makes balanced routes — similar time each (visits + walking) with the shortest walks — instead of minimising walking only (D-023).
- Theme: the app is light by default and no longer follows the system dark-mode setting (D-021).
- UI redesign across every screen (D-020): neutral palette with one coral accent for primary actions and selection, Inter typeface with an 8-step type scale, soft shadows and generous radii, light and dark themes.
- Explore: search-style city pill with a searchable city picker (flags), icon category tabs, responsive image-card grid (1–4 columns), floating Map/List switch and route tray; cards show the stop number when a place is in the route.
- Attraction: hero photo, category/UNESCO badges, "Good to know" tiles, grouped links and a sticky bottom bar with **Add to route**.
- Route and trip detail: map beside the stop list on desktop, stat tiles for totals, icon reorder/remove buttons; My Trips as a card grid; Profile with avatar and grouped settings; checklist sections in two columns with status pills.
- Navigation: bottom tab bar on phones, side rail on desktop (≥ 1024 px). Modals open as page sheets on phones and centred dialogs on tablets/desktop.
- Auth and onboarding: centred card layout with the brand mark; onboarding shows a progress bar.
- Micro-interactions: press-in scale, hover states on web, keyboard focus rings, in-place button spinners.

### Fixed

- CI: `pnpm typecheck` failed on a fresh checkout (`TS2882` on the `maplibre-gl` CSS import) because the `*.css` module types came only from the git-ignored `expo-env.d.ts` that `expo start` generates; `apps/mobile/tsconfig.json` now loads `expo/types` itself.
- Seed: an attraction that falls in two cities' bboxes (several Wikidata coordinates) is kept in the city where OSM confirms it, not the first alphabetically — Madrid Arena has a wrong second coordinate in Bilbao.
- Web: route-stop rows are no longer rendered as buttons when they don't open anything (they contained the reorder buttons: invalid nested `<button>`); checkbox, radio and selected states now reach the browser as ARIA attributes.

### Added

- Header app menu: the logo with a menu icon on every stacked screen (attraction, checklist, route, trip, edit profile, about) opens Explore, My Trips, Profile and About — no more dead ends on pages opened from a link.
- Explore search: a search bar with autocomplete over the city's attractions (accent-insensitive, EN/PT names); picking a suggestion adds the place to the route, the grid and map show every match.
- Profile → Preferences: **Theme** (Light / Dark), saved on the profile (`profiles.theme`, new migration) and applied at once across the app (D-021).
- Route builder: picks are ordered automatically for the shortest walk from the first pick; manual reordering (with "Reorder automatically" to undo), estimated walk between stops, and splitting a route of 5+ stops into independent routes — "Split here" or a proximity-based suggestion — each optimised and saved as its own trip (D-022).
- Checklist → Power: each destination plug type is shown with an illustration of the plug face.
- Explore list: a checkbox on each attraction card adds it to (or removes it from) the route without opening the attraction; checked cards show their stop number, and route notices (full route, new city) appear in the route tray.
- City coverage register [docs/CITIES.md](./docs/CITIES.md), generated from `cities.yaml` and the ingested data (`python -m wayfarer_pipeline cities-doc`; `ingest`, `seed` and `cities` rewrite it). CI fails when it is stale.
- CI `docs` job (`scripts/check-docs.mjs`): pull requests that change code, data or config without a CHANGELOG entry fail; user-facing changes without a README update get a warning.
